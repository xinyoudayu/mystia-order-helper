## 1 核心结论

**稀客的点单是「一个菜品标签 + 一个酒水标签」**，不是指定菜品：

```
SpecialOrder.RequestFoodTag      : int
SpecialOrder.RequestBeverageTag  : int
```

游戏自己提供了把标签翻译成文案的方法（`SpecialGuest.GetFoodTagText(int)` / `GetBevTagText(int)`，以及 `SpecialGuestsController.GetOrderFoodText(SpecialOrder)`），所以面板不需要自己维护标签表。

## 3 待运行时确认（M1 探针要打印的）

1. `GuestsManager.Instance` 在夜间场景外是否为 null（决定挂钩时机）；
2. `OnGuestSpawn` 触发时，`SpecialGuestsController` 是否已就绪、`SpecialGuest` 是否非空；
3. 常客与稀客的控制器类型区分方式（`TryCast<SpecialGuestsController>()` 是否可靠）；
4. `PeekOrders()` 的实际返回类型与订单生成时机（点单在入座后多久出现）；
5. `RunTimeStorage.Recipes` 是否等于「玩家已解锁食谱」（用测试菜谱 2000000002 对照）；
6. 需求标签与 `Sellable.Tags` 的匹配关系：是「菜包含该标签」还是「菜的主标签等于该标签」。

## 4 对实现的影响

- 推荐算法的输入非常干净：需求是两个 int 标签，候选集是「已解锁食谱 → 菜品 → 标签」；
- 不需要解析文案，也不需要维护标签字典；
- 主要工作量从「理解需求」转移到「拿到在场稀客 + 排序展示」。
