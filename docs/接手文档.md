## 2 五条铁律（违反任意一条都会返工）

### 2.1 性能：`OnGUI` 里什么都不许 new

游戏每帧会把界面画**两遍**（Layout + Repaint），所以 `OnGUI` 里的开销是双倍。
- 不许在 `OnGUI` 里拼字符串、`new List`、`new GUIStyle`、`new GUIContent`
- 所有文本和数据在采集阶段（每 0.5 秒一次）预生成好，绘制阶段只读
- v1.5.1 就是因为每帧现拼文字，玩家反馈"营业中偶尔卡顿"

### 2.2 IL2CPP：游戏对象不许跨帧持有

- `Sprite` / `Image` / 游戏里的 `Texture2D` 都可能在场景切换或 GC 后失效
- 要用就**当场**拷成自己 `new Texture2D(...)`，并设 `hideFlags = HideFlags.HideAndDontSave`
- 图集贴图关闭了 Read/Write，必须先 `Graphics.Blit` 到 `RenderTexture` 才能读

### 2.3 Harmony：Prefix 拦方法时，Postfix 也必须一起停

**这是本项目最贵的一次事故。** Prefix 返回 false 只跳过原方法体，**Postfix 照样执行**。
于是 Postfix 会拿着一个字段全是默认值的实例去登记状态，插件误判"面板已打开"，
连锁执行 暂停输入 / 禁止移动 / `timeScale = 0`，**游戏直接卡死**。

> 正确做法：Prefix 里设一个静态标记，Postfix 第一行查标记直接 return。
> 或者干脆别在这个入口拦。详见 `MOD制作经验文档.md` §4.5。

### 2.4 名字匹配：必须留"用户可填"的兜底

凡是"靠名字/编号认对象"的功能（头像、素材、角色），自动匹配一定会失败一部分。
设计时必须同时给出：**一个用户能自己填/自己放文件的入口**，且优先级高于自动识别。
本项目就是这个思路：`config\orderhelper-portraits\` 放图即用 > 映射表 > 别名 > 模糊匹配。

### 2.5 静默失败是禁止的

拿不到素材、匹配失败、跳过了某个角色——**都必须写日志说明缺谁**。
"没反应"是最难排查的 bug，因为没人知道该看哪里。

## 4 构建与发布（照抄）

### 4.1 编译

```powershell
cd "E:\game\mode\东方夜雀食堂\my mod"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1           # 只编译
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Install  # 编译并装机
```

**不要用 `dotnet build` / MSBuild。** 本机 NuGet 路径被拒，只能直调 `csc.dll`（脚本已处理）。
**不要直接 `& build.ps1`**，会被执行策略拒绝，必须包一层 `powershell.exe -ExecutionPolicy Bypass -File`。

### 4.2 装机前必查

```powershell
Get-Process -Name "Touhou Mystia Izakaya" -ErrorAction SilentlyContinue
```

有进程就**先让用户退游戏**，dll 被锁着拷不进去（不要替用户杀进程）。

### 4.3 打包

```powershell
python tools\make-release.py           # 出包到 release\
python tools\make-release.py --check   # 只校验，不写文件
```

它会做三件事：版本号三方校验（`OrderHelperPlugin.cs` / `build.ps1` / 装机 dll）、
生成安装说明、校验 zip 完整性。**新版本必须在脚本的 `NOTES` 里补一段本次变化，否则拒绝打包。**

产物两份：`夜雀点单助手-vX.Y.Z.zip`（给人下）+ `MystiaOrderHelper-vX.Y.Z.zip`（GitHub Release 资产名必须 ASCII）。

### 4.4 发版到 GitHub

仓库 `xinyoudayu/mystia-order-helper`（Public）。**目前只发到 v1.4.9**，
v1.5.0–v1.6.7 都还没建 Release，所以老用户点 `更新.bat` 会显示"已是最新"。
要发版：`git tag v1.6.7` + 上传 ASCII 名 zip（`release\MystiaOrderHelper-v1.6.7.zip`）。
**这属于改变远端可见状态，动手前先问用户。**

## 6 第一次上手：15 分钟验证

1. 启动游戏 → **进游戏约 2 秒后屏幕上方应弹一次版本小卡片，4 秒左右淡出，之后整个进程内绝不再弹**（日志里「版本提示已显示」「版本提示结束」各恰好一条）→ 进营业场景 → 按 **F8**
2. 应看到**纸片底 + 顶部一排头像**；点另一个头像，下方文字应跟着换
3. 新客人还没下单时，头像排里**不该**有 TA；下单后应自动出现
4. 搭配区每条应显示 `→ 菜＋酒`、`粉评N分 ｜ 净分 …`；**需要加料时多第三行** `｜ 加料 猪肉、洋葱 ｜ 赚N 余N份`
   （`[Behaviour] ConsiderExtras = false` 可关掉加料逻辑；日志里 `加料核算样例` 一行用来核对售价/成本是否离谱）
5. 日志里搜 `加料冲突表样例`（整局最多 3 条）：确认「禁用tag」是不是**大多数为空**。
   - 全空 → `BanTags` 没被游戏用来判定，防黑暗料理实际没生效，需要改用 `DataBaseCore.TagRules`（见经验文档 API 表）
   - 出现明显正常的 tag → 语义理解错了，先 `[Behaviour] AvoidDarkCooking = false` 关掉
   - 顺带确认 `TagRules 样例` 那一行是否打出来了（它是下一版最可能的依据）
6. 打开煮锅 → 右侧出现纸片色 `【料理】推荐（煮锅）`，顶部也有头像排
7. 点一条推荐 → 日志出现 `直填食材 … 选中>0 可制作组合>0`，面板里出成品
8. 打开酒水柜 → 右侧出现 `【酒水】推荐`
9. 外观异常时：配置里 `[Display] VanillaSkin = false` 重启，退回灰盒，用来判断问题是否皮肤引入

## 7 出问题怎么回滚

| 情况 | 做法 |
|---|---|
| 新编的版本有问题 | 从 `dist\` 或 `backup\` 拷回上一个 dll 到 `plugins\`，删掉其他 `MystiaOrderHelper-v*.dll` |
| 要退回稳定版 v1.5.2 | `backup\recon-2026-10-23\MystiaOrderHelper-v1.5.2.dll`（md5 `8A5B554D`，已实测通过） |
| 要看 2026-10-23 那次卡死事故的现场 | `backup\buggy-20261023-204101\`（出问题的 dll + 当时的全部源码） |
| 怀疑是外观改动引起 | 配置 `[Display] VanillaSkin = false`，比重装省事 |

**回滚原则**：`plugins\` 里永远只留一个 `MystiaOrderHelper-v*.dll`。
留两个会同时加载、互相打架（日志里会出现两遍「已加载」）。

## 9 和这位用户协作的方式（重要）

- **不要问能自己查的事**。先看代码、看日志、看文档再开口；卡住时说清"卡在哪、排除了什么、需要什么决定"。
- **不要猜角色名**。头像认不出来时留 `?`，让用户按坐标报——猜错比留空糟，玩家会以为是插件取错图。
- **改游戏文件前先确认游戏没在运行**，不要替用户杀进程。
- **打包 / 发版 / 提交**属于改变外部状态的操作，先问。
- 每轮改动完成后：**编译 → 装机（或告知已编译未装机）→ 同步文档 → 报告 md5**。
- 用户会用 `行.列` 报坐标（行自上、列自左），所以对照图要在每格左上角画坐标，且**报坐标用的图只能列待定项**（否则确认一批后坐标全移位）。
