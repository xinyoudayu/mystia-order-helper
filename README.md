# 夜雀点单助手（Mystia Order Helper）

《东方夜雀食堂》的 BepInEx 插件：把在场客人的点单、菜谱命中的喜好标签、**菜 + 酒** 的最佳搭配直接算好，摆在料理台和酒水面板旁边。点推荐项就能直接开做，不用再一格格翻菜谱。

- 游戏版本：0.29.4（Unity 2021.3.28f1 / IL2CPP）
- 前置：BepInEx 6.0.0-be.785（IL2CPP x64）
- 当前版本：**v1.6.7**（修卡顿：头像全场扫图降频 + 扫描预算真正生效 + 采集节拍 0.8 秒；已装机）
- 发布包：`release\夜雀点单助手-v1.6.7.zip`（上传 GitHub Release 用 `release\MystiaOrderHelper-v1.6.7.zip`）
- 上一稳定版：**v1.5.2**（采集性能优化 + 稀客影像识别，已实测通过）

## 功能

### 刷稀客好感：让她吃满所有单（v1.6.3 功能，v1.6.4 补按钮）

想让某位稀客多来几趟、把好感刷上去时，**在游戏里点一下就能开**，两条路都行：

- **主面板顶部**的「刷好感：关」→ 点一下变成「刷好感：开」（营业中随手切，不用暂停）
- **控制面板（F9）→【推荐口径】→「刷稀客好感」**（旁边还有「按预算推荐」开关，一并放在这里）

对应的配置项是 `[Behaviour] FavorFarm`（默认 `false`），在界面里点开关会自动写回配置文件，不用退出游戏手动改。

推荐会从「能花就花、利润优先」换成**先保粉评、再省钱**：

1. **这一单的上限 = 她手上现的钱 − 后面每单的「最低粉评价」**
   （最低粉评价 = 现有候选里最便宜的一份「菜 + 酒」粉评组合）
   —— 先把后面几单的钱扣出来，剩下的这一单随便花
2. **同样能粉评时挑更便宜的酒**（不是更贵的），省下的钱能让后面几单继续吃
3. **净分过 4 分（粉评线）之后不再追高分**，同分挑便宜的菜 —— 多出来的分数不会多给好感，却更贵

具体效果（总预算 2000、还剩 4 单、最低粉评价 300）：

```
预留 = 300 × 3 = 900      → 这一单上限 = 2000 − 900 = 1100
上完这单剩 900            → 后面 3 单每单正好还能吃 300 的粉评组合
```

- **切完之后，料理台和酒水柜旁边的推荐框也跟着变**（v1.6.5）：菜按主面板搭配的顺序排，酒水框把搭配里的那杯提到最前，
  刷好感时其余粉评酒按价格从低到高；在柜子界面里点开关同样即时刷新。
  「三位一体」这类特殊厨具也一样（v1.6.6：它的候选是另外算的一批菜，之前认不出是同一道菜）
- 只对**稀客**生效（常客没有好感、也不会吃满 5 单），常客完全不受影响
- 依赖 `[Behaviour] RespectFund = true`（要读钱包才能留钱），那项关了本项自动失效
- 客人状态行会标「刷好感」，一眼能看出现在是省钱口径
- 关掉（默认 `false`）就是 v1.6.2 的正常口径：能花就花、同样粉评挑更赚的

### 按客人的预算配酒（v1.6.2 口径）

客人身上带多少钱是有限的。以前插件只管「哪杯酒能凑粉评、卖得贵」，不看价，
搭配价格远超客人钱包时他付不起，直接就是黑评。

现在每位客人都会读一次钱包（游戏内 `GuestGroupController.GetFund`），并算出**这一单的上限**：

```
还有单没上  →  上限 = 他手上现的钱
最后一单    →  上限 = 手现金 + 余量（本次到店总预算的 10%，夹在 30~300 之间）
```

**不再按单数均分**（v1.6.1 是 `剩余钱 ÷ 剩余单数`）。均分把第一单压得太死——
预算 1000 却只敢花 500，本来吃得起的好菜也推不出来。现在只要「这一单花掉的钱不超过他手上的现钱」，
最后一单才允许小幅超支，所以「预算 1000，第一单 800、最后一单 300」这种搭配是可行的（总共 1100，超一成）。

配酒顺序因此变成：

1. **超过这一单上限的酒直接不选**
2. 付得起的里面先保粉评；同样粉评时优先给后面几单留点钱（留下手上现钱的 20%），然后比利润（售价）、库存
3. 付得起的里面一杯粉评的都没有 → 退回**最便宜的那杯粉评**，并在界面上明确标出超了多少
   （不偷偷降成橙评，让你自己决定要不要冒这个险）
4. 一杯粉评都没有（真凑不出）→ 按老规则给，界面照旧显示「凑不出粉评」

界面上会多一行预算信息：

```
    → 豆腐锅[煮锅]＋清酒
       粉评 6分  ｜ 净分 菜4 酒2
       ｜ 价 780  预算余 1500
```

最后一单动用了余量：

```
       ｜ 价 300  预算余 200  略超100（余量内）
```

超过上限才会警告：

```
       ｜ 价 1800  预算余 1200  ⚠超600，可能黑评
```

- 客人详情的状态行也会写「预算余 1500」，推荐框标题写「余 1500」
- 酒水推荐框的每一杯都带单价，付不起的标 `⚠超预算`（菜价按当前最推荐的那道菜算）
- 读不到钱（`GetFund` 返回 0 或抛异常）时，整个功能自动失效，退回 v1.6.0 的行为，不会把推荐清空
- 不想要：`[Behaviour] RespectFund = false`

### 加料推荐（v1.6.0 口径）

推荐不只看菜谱自带的标签，**追加食材（加料）的标签也算分**。加料的目标是**让这一道菜自己就能粉评（净分 ≥ 4）**，
不再靠酒水补分。凑出来了就写在搭配下面：

```
    → 豆腐锅[煮锅]＋清酒
       粉评 6分  ｜ 净分 菜4 酒2
       ｜ 加料 猪肉、洋葱 ｜ 赚38 余12份
```

- **一锅最多 5 个食材，含菜谱自带的**，所以加料槽 = 5 − 菜谱食材数（菜谱本身要 5 个食材的就没法加料）
- **加料不改变售价**，只是多消耗食材 —— 目标分（4 分）够了就停，不会白烧食材
- **菜怎么排**：先看你喜欢/讨厌的 tag 命中数（净分），命中数一样才比利润率
- **酒怎么挑**：先保证「配上这道菜还能粉评」，这一档里按利润（售价）→ 库存数量
- 「余12份」= 这一道做完后，用到的最紧张那样食材还剩 12 份，避免把稀有食材吃到见底
- 点推荐条目一键制作时，**加料会一起放进锅里**（菜谱食材 + 加料 = 一锅 ≤ 5 个）
- 不想要这套逻辑：`[Behaviour] ConsiderExtras = false`（退回只看菜谱标签）

### 加料怎么挑（v1.6.0）

加料只过一道检查：**禁用 tag**。加料带进来的新味道如果在这道菜的禁用表里（游戏数据 `BanTags`），
这份料直接不选——下去就变黑暗料理。

**不再检查「会不会顺便凑成另一道菜」**（v1.5.7 曾经这么做，v1.5.9 撤掉了）：如果加料后锅里也能做出别的菜，
游戏面板会照常把所有能做的菜列出来，由你自己点选做哪道——同材料两道菜本来就该玩家决定，
插件不该替他砍加料。v1.5.7 那个检查条件过宽，实测一局撤回 85 份加料、15 次一键制作一次都没带上料。

加料后如果一个组合都匹配不上（说明这些食材在游戏眼里做不出菜），才会自动退掉最后一味。

全部候选都被挡掉时，搭配下面会写：

```
       ｜ 加料会做成黑暗料理
```

想知道加料有没有真的进锅，搜日志里的 `游戏接受的加料=`——那个数大于 0 就是成了。

这不是插件没找到，而是**故意不加**——加了就是黑暗料理。

- 关掉这层检查：`[Behaviour] AvoidDarkCooking = false`（退回 v1.5.6 的行为，可能会推荐冲突组合）

### 启动时的版本提示

### F8 主面板

上半是**头像横排**（稀客显示游戏自带的立绘头像，常客是名字首字占位），一行放不下自动换行；
点任意一个头像，下半展开这位客人的**菜 + 酒搭配**推荐（最多 3 组）：

```
[头像] [头像] [头像] [头像] [头像]
────────────────────────
◆ 魂魄妖梦（稀客）  桌位 6  剩1单
点菜：我想要家常的料理
点酒：请给我水果的饮料
    [菜 + 酒 搭配]
    → 豆腐锅[煮锅]＋清酒
       粉评 6分  ｜ 净分 菜3 酒3
```

**还没点单的客人不显示**：没有单就没有可推荐的内容，列出来只会占位置。
客人点完单才会出现在头像排里；已上完菜在等下一单的同样不显示。

点开的这位客人显示名字、桌位、点单原文、剩余单数：

```
◆ 魂魄妖梦（稀客）  桌位 5  剩1单
点菜：我想要家常的料理
点酒：酒水标签 12
    [菜 + 酒 搭配]
    → 豆腐锅[煮锅]＋清酒
       粉评 6分  ｜ 净分 菜3 酒3
```

- **净分** = 命中的喜好标签数 − 命中的厌恶标签数（菜、酒分开算，负数说明点了会掉评价）
- **合计分** = 菜净分 + 酒净分，游戏按合计分给评价：**≥4 粉评**、3 橙评、2 绿评、1 紫评、否则黑评
- 稀客只在**能凑出粉评**时才推荐组合；凑不出来就降级显示“命中标签最多的那一菜一酒”
- 常客按精确菜名 / 酒名推荐，不受粉评限制

### 料理台旁 / 酒水面板旁

打开厨具面板或酒水柜时，旁边会出现对应的推荐框：

- 料理框列出**当前厨具能做的**、且命中的菜，标题写清厨具名（特殊厨具会显示“三位一体”这类名字）
- 酒水框列出有货的酒水
- 每行标注 `(净N分) [粉评 合计6分] 可做/缺料`，缺料会写缺哪种食材、差多少
- 已经上过菜、正在等下一轮的客人不会出现在推荐框里
- 点推荐项 → 自动填食材 → 自动开做（可在 F9 里关掉一键制作）

### F9 控制面板

- 字号 12–32
- 常客是否显示
- 一键制作开关
- 三个窗口（主面板 / 料理框 / 酒水框）的位置与大小：`←→↑↓` 移动、`宽± / 高±` 缩放、`默认` 复位
- 导出客人日志、恢复默认

位置和大小会自动存进配置，下次进游戏沿用；拖动窗口本身也会记住新位置。

### 头像

- **稀客**：从游戏的立绘里实时取（身体层 `×Main_0,1` + 表情层 `×Eyes_0,1` 按 pivot 对齐合成，
  再按眼睛位置裁成头肩特写），拷成插件自己持有的贴图并按名字缓存，跨场景不失效。
- **常客**：没有立绘，显示名字首字占位。
- **认不出来**：退回首字占位，不会留空白；日志里会记录「头像新增 N 位（共 M）：名单」便于排查。
- **想换头像**：把图片丢进 `<游戏目录>\BepInEx\config\orderhelper-portraits\`，
  **文件名 = 面板上显示的名字**（如 `茨木华扇.png`），优先级高于所有自动识别。
  查询顺序：精确 → 繁简归一 → 双向包含（`咲夜.png` 能命中「十六夜咲夜」）。任意尺寸会自动裁方缩到 48×48。
- 仓库里已从游戏自带的头像素材包导入 **85 个角色**（工具链在 `tools\`，见下）。

### 已知限制

- **没有点击防误触**：游戏的点击判定不走 Unity 的 UI 事件系统，插件在它之外拦不住，
  点插件面板上的按钮时可能同时触发背后的厨具/酒水面板。
  （2026-10-23 曾试过在 `OnPanelOpen` 加 Harmony Prefix 拦截，**会导致游戏卡死**：
  Prefix 返回 false 只跳过原方法体，Postfix 仍会执行并对未初始化的实例登记"面板已打开"，
  连锁触发暂停输入 / `timeScale=0`。已整体放弃，细节见 `docs\MOD制作经验文档.md` §4.5。）
- 字号调大（>24）时窗口不会自动变宽，需要手动加宽。

## 安装

1. 确认游戏已装 BepInEx 6.0.0-be.785（IL2CPP 版），`<游戏目录>\BepInEx\core\BepInEx.Unity.IL2CPP.dll` 存在
2. 从 [Releases](../../releases) 下载最新 zip
3. 解压，把 `BepInEx\plugins\MystiaOrderHelper-vX.Y.Z.dll` 放进 `<游戏目录>\BepInEx\plugins\`
4. 启动游戏，日志里出现 `夜雀点单助手 vX.Y.Z 已加载` 即成功
5. 按 F8 开主面板，F9 开控制面板

卸载：删掉 plugins 里那个 dll 和 `BepInEx\config\local.mystia.orderhelper.cfg`。

## 更新


## 从源码构建

需要 .NET SDK（Roslyn 编译器）与本机 BepInEx 的 interop 程序集：

```powershell
# 改 build.ps1 顶部的 $GamePath 指向你的游戏目录
powershell.exe -NoProfile -ExecutionPolicy Bypass -File build.ps1
# 产物：dist\MystiaOrderHelper-vX.Y.Z.dll
```

注意：

- 不要用 `dotnet build` / MSBuild（本项目没有 csproj，走 Roslyn `csc.dll` 直编）
- 版本号要改三处：`src/OrderHelper/OrderHelperPlugin.cs` 的 `Version`、`build.ps1` 的 `$version`、文档；打包时还要在 `tools/make-release.py` 的 `NOTES` 里补一段本次变化（不补它会拒绝打包）
- 发版：`python tools/make-release.py`，产物在 `release\`（流程见 `docs\MOD制作经验文档.md` §15）
- `build.ps1` / `scripts\game.ps1` 的 `$GamePath` 默认值是作者机器上的路径，请改成你自己的
- 想一键「编译 + 装进游戏 + 启动」，用 `scripts\dev.ps1`（游戏开着时它会拒绝部署，不会替你关游戏）
- `.ps1` 请保持 ASCII 或 GBK 保存（PowerShell 5.1 按系统 ANSI 读脚本，UTF-8 中文会乱码）

## 配置

`<游戏目录>\BepInEx\config\local.mystia.orderhelper.cfg`：

```ini
[General]

SettingsKey = F9

[Display]
FontSize = 20
ShowNormalGuests = false
VanillaSkin = true      # false = 回到 v1.5.2 的灰盒外观

AvoidDarkCooking = true # 加料前检查会不会把菜做成黑暗料理（禁用 tag / 不成别的菜）

SnapshotLog = false
UiProbe = false         # UI 素材侦察，会扫全场并写 dump，只在改 UI 时临时开

[Layout]
MainX = 40
MainW = 560
CookerHintX = 1904
...
```

改配置要在游戏退出后进行，否则游戏关闭时会把内存里的值写回去。

## 评分规则备忘

游戏本身对稀客的喜好标签计分：命中 1 个喜好 +1、命中 1 个厌恶 −1，菜与酒相加后定评价档位。本插件的“净分 / 合计分 / 粉评”就是把这套规则显式算出来，不改变游戏判定。

**两套口径要分清**（v1.6.0 起）：

- **显示口径**（评价档位、合计分）：照游戏来，菜 + 酒相加。粉评 = 成对且合计 ≥ 4。
- **推荐口径**（排序、加料目标）：只看菜自己。排序按命中标签数（净分）→ 利润率；加料目标固定 4 分（单单食材就粉评），不拿酒分抵。

两者分开是有原因的：v1.5.x 把加料目标写成 `4 − 酒分`，酒常有 2~3 分，菜自己早够了 → 加料规划一份都不挑，
表现为“永远没有加料”。

标签 id 为负数不是合法标签，而是“这张单没有这一项”：`foodRequest = −1` 表示还没点单，`beverageRequest = −1` 表示酒水不限。
